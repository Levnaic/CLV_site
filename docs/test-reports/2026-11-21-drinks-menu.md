## Findings

**F1 (low, EN pages, still present): mixed number format.** `/en/` shows prices with a decimal point
(`4.00 €`) but volumes with a decimal comma (`0,25 l`, `0,355 l`, `0,75 l`) in the same row, because `size` strings
from `data/drinks.json` are printed verbatim. Fix idea: localise the decimal separator of sizes for en
(`0.25 l`). Owner: frontend agent (`build.py`).

**F2 (low, accessibility): the tablist has no accessible name.** `<div class="drink-tabs" role="tablist" id="drinkTabs">`
has neither `aria-label` nor `aria-labelledby`. Screen readers announce "tab list" without context. Not a WCAG
failure on its own (axe rule `aria-tablist` does not require a name), but recommended. Fix idea: add
`aria-label` with the section title ("Getränkekategorien" / "Drink categories" / "Categorie di bevande"). Owner:
frontend agent (`build.py`).

**F3 (cosmetic, 1200-1440 px): orphan second row of tabs.** With 8 tabs the strip is 6 + 2 at 1440 px (and at
1200). Looks intentional (centred), not a defect; mention only in case a single row is wanted (shorter labels).

**F4 (carried over, not re-checked, JS off):** panels carry `aria-labelledby` and `tabindex="0"` before JS adds
`role="tabpanel"`. Only relevant without JS (extra tab stops). Not tested in this run.

**F5 (data sanity, owner to confirm):** "Weinschorle 0,2 l 6,00 EUR" is dearer than "Weißwein 0,2 l 5,00 EUR";
check against the printed menu. TODO.md still lists the Italian/English text check as open.
